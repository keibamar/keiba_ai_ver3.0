# RaceContextCenter (Chronicle) 動作確認

Chronicle は date_str と place_id を受け取り、race_id リストを生成して返す役割を担う。
`src/managers/race_schedule_dataset_manager.py` と `src/datasets/race_schedule/`
（`model` / `transform` / `validate`）が実装の中心。

全テストはオフライン（通信不要）で実行できる。JRA公式カレンダーの取得テストは
DataHarvester (Reaper) の `test_jra_calendar_scraper.py` に分離されている。

## 実行方法

```bash
# 全テスト実行（詳細表示）
python -m pytest tests/test_race_schedule_dataset_manager.py -v

# print文の内容も表示したい場合は -s を追加
python -m pytest tests/test_race_schedule_dataset_manager.py -v -s
```

## テスト内容の要約

テストは大きく2グループに分かれる。

### グループ1: race_id の算出（7関数・28ケース）

race_id のフォーマットは `YYYYCCTTDDNN`（年/開催場/開催回/開催日目/レース番号）。
期待値は `transform.build_race_ids_for_day` / `model.MAX_TIMES_PER_YEAR` 等を
使って独立に組み立て、新実装の出力と比較する。

- **test_get_daily_id_returns_expected** [9ケース]:
  `get_daily_id(place_id, race_day)` — 指定日・指定開催場のrace_idリストを返す。
  カレンダーを参照して実際の開催回(times)・開催日目(days)を取得し、
  `build_race_ids_for_day` で期待値を組み立てて一致を確認する。
  - `place_id=0`（全場）の開催日・非開催日・複数場同日開催のケースを網羅
  - `place_id=5`（京都）・`place_id=6`（中山）の場所絞り込みも確認

- **test_get_past_weekly_id_returns_expected** [4ケース]:
  `get_past_weekly_id(place_id, race_day)` — 7日前〜当日の7日分を連結したリストを返す。
  `get_daily_id` を7回呼んだ結果と一致することを確認する。

- **test_get_past_year_id_returns_expected** [4ケース]:
  `get_past_year_id(place_id, race_day)` — race_day を起点に過去1年分の race_id リストを返す。
  件数・先頭・末尾のリテラル値でアサート（例: place_id=0, race_day=2025/6/1 → 1464件）。
  race_dayが年初（2025/1/1）の場合は0件になることも確認。

- **test_get_year_id_all_returns_expected** [6ケース]:
  `get_year_id_all(place_id, year)` — カレンダーに依存せず、開催回(1〜6)×
  開催日目(1〜12)の全組み合わせ×12Rを生成する。
  `model.MAX_TIMES_PER_YEAR` / `model.MAX_DAYS_PER_TIMES` のループで組み立てた
  期待値と一致することを確認する。

- **test_get_past_weekly_place_id_returns_expected** [2ケース]:
  `get_past_weekly_place_id(race_day)` — 過去1週間に開催があった place_id のリストを返す。
  例: 2025/1/13 → `[6, 7]`（中山・中京）。

- **test_get_daily_place_id_returns_expected** [2ケース]:
  `get_daily_place_id(race_day)` — 指定日に開催がある place_id のリストを返す。
  非開催日（2025/1/7）は空リストになることも確認。

- **test_get_place_id_list_from_race_id_list_returns_expected** [1ケース]:
  `get_place_id_list_from_race_id_list(race_id_list)` — race_id リストから
  place_id の一意リストを抽出する。中山（place_id=6）の年間 race_id を渡すと
  `[6]` のみが返ることを確認。

### グループ2: カレンダー行ごとの組み立て（2関数・2ケース）

- **test_get_year_id_calendar_returns_expected** [1ケース]:
  `get_year_id_calendar(place_id, year)` — カレンダー CSV の各行（開催回・開催日目）
  ごとに `build_race_ids_for_day` を呼んで連結する実装が正しいことを確認する。
  中山（place_id=6、年間複数回開催）を対象に、重複が発生しないこと、
  およびカレンダーの各行から独立に組み立てた期待値と一致することをアサートする。

- **test_get_next_weekly_id_returns_expected** [1ケース]:
  `get_next_weekly_id(place_id, race_day)` — 当日〜6日後の7日分を連結したリストを返す。
  `get_daily_id` を7回（offset 0〜6）呼んだ結果と一致することを確認する。

## race_id フォーマットのメモ

```
YYYY CC TT DD NN
2025 06  1  1 01  → "202506010101"（2025年 中山 1回 1日目 1R）
```

| 桁 | 意味 | 例 |
|---|---|---|
| YYYY | 年 | 2025 |
| CC | 開催場コード（2桁） | 06=中山, 05=東京, 07=中京 |
| TT | 開催回（1〜6） | 01 |
| DD | 開催日目（1〜12） | 01 |
| NN | レース番号（01〜12） | 01 |
