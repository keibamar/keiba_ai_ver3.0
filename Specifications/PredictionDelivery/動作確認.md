# PredictionDelivery (Herald) 動作確認

Herald は Chronicle から渡された race_id について、Atlas から予想結果・配当結果を取得し、
予想テキスト・配当結果レポートを生成してGmail/Xに配信するモジュール。
実装は `src/output/prediction_publisher.py`（予想テキスト生成・配信）と
`src/output/return_report.py`（配当結果レポート・回収率集計）。
2つのテストファイル・15テストで構成され、全てオフライン（SMTP/Xはモック化）で実行できる。

## 実行方法

```bash
# Herald関連の全テストを実行
python -m pytest tests/test_prediction_publisher.py tests/test_return_report.py -v

# print文の内容も表示したい場合は -s を追加
```

### 代表テストのみ実行（print確認用）

```bash
python -m pytest tests/test_prediction_publisher.py::test_make_race_text_writes_expected_content tests/test_prediction_publisher.py::test_send_email_sends_via_smtp tests/test_prediction_publisher.py::test_post_text_data_creates_tweet tests/test_return_report.py::test_make_return_text_writes_expected_content tests/test_return_report.py::test_post_race_returns_posts_tweet -v -s
```

## 処理フロー（参考）

```
race_day_scheduler から呼ばれる順序（予想テキスト）:
1. prediction_publisher.make_race_text(race_day, race_id)
     ├─ race_card_dataset_manager.get_race_cards(...) で出馬表(score/rank)を取得
     ├─ extract_top5_pred(race_card_df)  # rank1〜5の馬番・馬名を抽出
     └─ texts/race_prediction/{date}/{race_id}.txt に書き出し
2. race_day_scheduler.post_race_pred(race_id, race_day)
     └─ prediction_publisher.post_text_data(text_path) → tweepy.Client.create_tweet
3. prediction_publisher.send_race_pred(race_day, race_id)
     └─ prediction_publisher.send_email(text_path) → smtplib.SMTP_SSLでメール送信

配当結果レポート（race_day_scheduler.post_pred_returnから呼ばれる想定）:
1. return_report.make_return_text(place_id, race_day)
     ├─ get_win_result / get_place_result / get_trio_box_result（race_id_listを集計）
     │    └─ race_card_dataset_manager.get_race_cards + race_info_dataset_manager.get_race_return_csv_for_race
     ├─ write_win_hit_text / write_place_hit_text / write_trio_hit_text
     └─ texts/race_returns/{date}/{place}_pred_score.txt に書き出し
2. return_report.post_race_returns(place_id, race_day)
     └─ prediction_publisher.post_text_data(text_path) → tweepy.Client.create_tweet
```

## テスト内容の要約

### test_prediction_publisher.py（予想テキスト生成・配信、7件）

- **test_extract_top5_pred_returns_top5_in_rank_order**: `rank`列でソートし、
  上位5頭の馬番・馬名を `[馬番, 馬名]` のリストで返す純粋関数。
- **test_make_race_text_writes_expected_content**: 出馬表CSV（score/rank付き）から
  予想テキストを生成。日付行・開催情報行（場名+R番+レース名+発走時刻）・
  予想印（◎○▲△☆）+上位5頭・ハッシュタグの構成を確認。
- **test_make_race_text_skips_when_no_rank_column**: `rank`列が無い場合は
  テキストファイルを生成しない（スキップ）ことを確認。
- **test_send_email_sends_via_smtp**: `smtplib.SMTP_SSL` をモック化し、
  `login → send_message → quit` の呼び出し順と、件名（1行目+2行目）・
  本文（4行目以降）の組み立てを確認。
- **test_send_email_missing_file_does_not_send**: ファイルが存在しない場合は
  SMTP接続自体を行わないことを確認。
- **test_post_text_data_creates_tweet / test_post_text_data_no_file_does_not_raise**:
  `tweepy.Client` をモック化し、ファイル内容をツイートとして投稿することを確認。
  ファイルが無い場合は例外を出さずに空のまま終了することも確認。

### test_return_report.py（配当結果レポート・回収率集計、8件）

- **test_get_win_result_hits_rank1_horse / test_get_place_result_hits_rank1_horse /
  test_get_trio_box_result_hits_top3_within_box**: 予想rank1位の馬が単勝/複勝/
  三連複BOXで的中した場合の的中率・回収率・的中レース番号を算出する3関数を確認。
  サンプルレースカード（rank1=馬番5, rank2=馬番9, rank3=馬番7）に対する配当データで検証。
- **test_write_win_hit_text_format / test_write_place_hit_text_format /
  test_write_trio_hit_text_format**: 上記の結果をテキスト行
  （`"◎単勝回収率:160.0%  (的中レース:1 R)\n"`等）に整形する関数を確認。
- **test_make_return_text_writes_expected_content**: 上記を統合し、
  `texts/race_returns/{date}/{place}_pred_score.txt` を生成。見出し・各回収率行・
  ハッシュタグの構成を確認。
- **test_post_race_returns_posts_tweet**: `tweepy.Client` をモック化し、
  生成したレポートテキストをツイートとして投稿することを確認。
- **test_post_daily_race_returns_posts_for_each_racing_place**（2026-06-18追加）:
  `post_daily_race_returns(race_day)` — 全place_idについて`get_daily_id`で
  開催の有無を確認し、開催があったplace_idのみ`make_return_text`/
  `post_race_returns`を呼ぶことを確認（2024/10/20は04_nigata/05_tokyo/08_kyotoの
  3場のみ開催）。`bat/TodayRace/today_race_rerturns.bat`
  → `scripts/run_today_race_returns.py`から呼ばれる新規実装
  （旧`calc_returns.py`の`post_race_rerurns`の当日全場分呼び出しに相当）。
