# HTMLFactory (Forge) 動作確認

Forge は Chronos から渡された race_id について、Chronicle（カレンダー）と Atlas（レース結果・
血統データ）から情報を取得し、`public_html/` 配下に静的HTMLを生成するモジュール。
4つのテストファイル・24テストで構成され、全てオフライン（既存の `data/` を参照、
出力先のみ `tmp_path` に切り替え）で実行できる。

## 実行方法

```bash
# Forge関連の全テストを実行
python -m pytest tests/test_html_manager.py tests/test_daily_index_generator.py tests/test_race_page_generator.py tests/test_horse_report_generator.py -v

# print文の内容も表示したい場合は -s を追加
```

### 代表テストのみ実行（print確認用）

```bash
python -m pytest tests/test_html_manager.py::test_add_race_day_appends_to_existing_file tests/test_daily_index_generator.py::test_make_daily_index_page_generates_index_html tests/test_race_page_generator.py::test_make_race_card_html_generates_full_page tests/test_horse_report_generator.py::test_horse_report_to_html_structure -v -s
```

| テストファイル | テスト数 | 対応する実装 | 役割 |
|---|---|---|---|
| `test_html_manager.py` | 4 | `src/managers/html_manager.py` | カレンダーJS（`raceDays.js`）への日付追加 |
| `test_daily_index_generator.py` | 3 | `src/logic/html_generator/daily_index_generator.py` | 日次レース一覧ページ（`races/{date}/index.html`） |

| `test_horse_report_generator.py` | 7 | `src/logic/html_generator/horse_report_generator.py` | 出走馬詳細レポート（レースページに埋め込まれるHTML断片） |
| **合計** | **24** | | |

## 処理フロー（参考）

```
race_day_scheduler から呼ばれる順序:
1. html_manager.add_race_day(race_day)              # raceDays.js にレース開催日を追加
2. daily_index_generator.make_daily_index_page(race_day)  # 日次一覧ページ生成
3. （レースごとに）race_page_generator.make_race_card_html(date_str, place_id, race_id)
     ├─ 出馬表テーブル（race_card_builder.make_race_cardの結果を整形）
     ├─ レース結果・配当（確定後のみ）
     ├─ コース別データセクション（平均タイム・平均馬体重・血統別成績・平均人気・枠番馬番）
     └─ 出走馬ごとに horse_report_generator.build_horse_report → horse_report_to_html
          └─ 過去成績（近5走）・芝/ダート別サマリ（最速上り・平均上り・平均通過位置）
```

## テスト内容の要約

### test_html_manager.py（カレンダーJS更新）

- 新規ファイル作成・既存配列への追記・重複日のno-op・配列が見つからない場合の
  `ValueError` の4パターンを確認。`public_html/assets/js/raceDays.js`（`window.racedays`）
  を更新する処理で、Forge専用（Chronos/Chronicleとは別系統）。

### test_daily_index_generator.py（日次レース一覧）

- **test_load_race_info_returns_real_race_names**: `texts/race_calendar/race_time_id_list/`
  の実データから、race_idごとの発走時刻・レース名を読み込む。
- **test_group_place_races_and_build_table_rows**: race_idリストを開催場別にグループ化
  （`group_place_races`）し、HTMLテーブル行を組み立てる（`build_table_rows`）。
  レースページがまだ生成されていない場合は `<a href>` を出さないことも確認。
- **test_make_daily_index_page_generates_index_html**: 上記を統合し、実際に
  `public_html/races/{date}/index.html` を生成。見出し・開催場テーブル・前後日リンク
  （未生成時はdisabled表示）を確認。

### test_race_page_generator.py（レース個別ページ、最大のテストファイル）

- レース情報・走破タイム・馬体重・人気・枠番馬番・血統別成績の各セクション生成関数
  （`generate_*_info`系）を実データで個別に確認。
- **test_make_race_card_html_generates_full_page**: 全セクションを統合した
  フルページ生成。ナビゲーション・出馬表テーブル・レース結果・コース別データ・
  出走馬詳細レポートの埋め込みまで一通り確認。
- **test_make_daily_race_card_html_generates_only_available_races**: 1日分のレースのうち
  データが存在するレースのみページを生成することを確認。

### test_horse_report_generator.py（出走馬詳細レポート）

- 血統データ・horse_id_mapの読み込み（旧フォーマットとのキー一致確認含む）。
- **test_build_horse_report_structure**: 近5走成績（`recent5`）・芝/ダート別サマリ
  （`surface_summary`：最速上り・平均上り・平均通過位置）を組み立てる
  `build_horse_report` を実データで確認。
- **test_horse_report_to_html_structure**: 上記をHTML文字列に変換する
  `horse_report_to_html`。馬が見つからない場合のエラー表示も確認。

### 実行時に出る実装側ログについて

`race_page_generator.py` / `horse_report_generator.py` は、データが無い場合に例外を投げず
`return None` 等で安全にスキップする実装になっている。スキップ時のログは
`ℹ️ [スキップ/エラーではありません]` で統一して明示している（本来の問題を示す箇所のみ
`❌ [要確認/エラー]` を使用）。

| ログ | 発生条件 | エラーか |
|---|---|---|
| `ℹ️ [スキップ/エラーではありません] レースカード未生成` | 出馬表CSVがまだ生成されていない | 否（正常） |
| `ℹ️ [スキップ/エラーではありません] レース結果データなし（未確定）` | レースがまだ確定していない | 否（正常） |
| `ℹ️ [スキップ/エラーではありません] 配当結果データなし（未確定）` | 配当がまだ確定していない | 否（正常） |
| `ℹ️ [スキップ/エラーではありません] レース情報未蓄積` | 近隣日の同条件検索で対象レースの情報が未蓄積 | 否（正常） |
| `ℹ️ [スキップ/エラーではありません] 指定日に開催なし` | その日にその開催場でレースがない | 否（正常） |
| `ℹ️ [スキップ/エラーではありません] 平均タイムの該当データなし（サンプル不足）` | 障害戦等、サンプル数が少ないコース・クラスの組み合わせ | 否（正常） |
| `❌ [要確認/エラー] 不明な開催場名` | `course_name` がPLACE_LISTに存在しない | 要確認（データ不整合の可能性） |
| `❌ [要確認/エラー] {horse_name} のレポート作成に失敗` | `build_horse_report`等で例外が発生 | 要確認（実際の例外） |
