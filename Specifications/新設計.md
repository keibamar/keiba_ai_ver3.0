# 新設計

## 1. データセット（CSV）のフォルダ構成（data/）

CSV を扱う場合、データの種類ごとにフォルダを分けると保守性が高くなります。

例:

```
project/
├── data/                 ← CSV（非公開・gitignore）
│   ├── horse/
│   ├── race_info/
│   ├── race_result/
│   └── race_schedule/
│
├── public_html/          ← HTML（公開OK・Git管理）
│   ├── index.html
│   ├── dailyindex.html
│   ├── racepage/
│   │   ├── 20250101_01R.html
│   │   └── ...
│   └── assets/
│       ├── css/
│       ├── js/
│       └── images/
│
└── src/
    ├── datasets/
    ├── managers/
    ├── logic/
    ├── output/
    ├── config/
    └── utils/


ポイント:

- Dataset 層は CSV を直接操作しない
- Manager 層が CSV の読み書きを担う
- Dataset 層は DataFrame の構造・変換のみを担当する
- `data/` は `.gitignore` に入れても良い（必要なら `raw/` と `processed/` に分ける）

## 3. 各層の役割（最適化された設計）

### Dataset 層（`src/datasets/`）

役割: データ構造・変換・バリデーション

- DataFrame のスキーマ定義
- CSV → DataFrame の変換ロジック
- DataFrame の正規化
- 欠損値チェック、型変換、日付の正規化、カラム名の統一

注意: Dataset 層は I/O を持たない（CSV の読み書きは Manager 層の責務）

### Manager 層（`src/managers/`）

役割: CSV の読み書き・永続化・検索

- CSV を読み込んで DataFrame を返す
- DataFrame を CSV に保存する
- データの更新、検索、キャッシュ管理、存在チェック

方針: `pandas` を扱うのは Manager 層。Dataset 層は pandas を直接触らず DataFrame を受け取るだけにする。

### Logic 層（`src/logic/`）

役割: アプリケーションロジック

- 予想生成（RacePredictionEngine）
- HTML 生成、スクレイピング、平均値計算
- スケジューリング（定期処理や実行タイミング管理）

実装指針:

- Manager 層を呼び出してデータを取得する
- Dataset 層の構造に従って処理を行う

### Output 層（`src/output/`）

役割: 外部出力（POST / メール / HTML 配信）

- POST 送信、メール送信、HTML 配信
- 将来的な Slack / LINE / Discord 連携もここに集約する

### Config 層（`src/config/`）

役割: パス・定数・共通リスト

- `data/` のパス、HTML 出力先、レース場一覧、曜日一覧、馬場コード一覧など

## 4. 全体構造（まとめ）

推奨構成:

```
data/        ← CSV（生データ・中間データ）
src/
  datasets/  ← DataFrame の構造・変換
  managers/  ← CSV の読み書き
  logic/     ← 予想・スクレイピング・スケジューラ
  output/    ← POST・メール・HTML 出力
  config/    ← PATH・定数
  utils/     ← 共通関数
```

この構成は再現性・拡張性・保守性・自動化・将来の Web サービス化に強い設計です。
