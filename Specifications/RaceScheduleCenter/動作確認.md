# RaceScheduleCenter (Chronos) 動作確認

Chronos はレース当日のオーケストレーターで、Chronicle (RaceContextCenter) から race_id を受け取り、
Oracle / Forge / Herald を順に呼び出す司令塔。実装は `src/logic/scheduler/race_day_scheduler.py`。

## 関数の役割一覧

| 関数 | 役割 | テスト対象 | 対応するbat |
|---|---|---|---|
| `post_race_pred(race_id, race_day)` | 予想テキストのファイルパスを組み立て、`prediction_publisher.post_text_data` に渡す | ✅ | （`post_daily_race_pred`内から呼ばれる） |
| `post_pred_return(place_id, race_day)` | 配当結果テキストのファイルパスを組み立て、`prediction_publisher.post_text_data` に渡す | ✅ | - |
| `post_daily_race_pred(race_day)` | レース当日のメインループ（20分前投稿・1分ポーリング・30分待機）| ❌ 対象外 | `TodayRace/post_today_race.bat` |
| `_extract_race_time(info)` / `_extract_race_name(info)` | `scrape_race_card`のinfoから発走時刻(HHMM)・レース名を抽出する純粋関数 | ✅ | - |
| `make_time_id_list(race_day)` | 指定日の全場の出馬表をスクレイピングし、`[race_time, race_id, race_name]`を発走時刻順に組み立てる | ✅（network） | - |
| `update_weekly_time_id_list(base_day)` | 次の7日分について`make_time_id_list`を実行し、`race_card_dataset_manager.save_time_id_list`で保存する | ✅ | `TodayRace/make_time_id_list.bat` |
| `make_html_prev_day(race_day)` | 翌日分の出馬表・予想・HTMLを事前生成する | ✅ | `MakeHTML/make_html_prev_day.bat` |
| `update_daily_html(race_day)` | 当日分のレース結果・配当結果を取得し、HTMLを再生成する | ✅ | `MakeHTML/update_daily_html.bat` |

`post_daily_race_pred` はライブループ（`sleep(60)` / `datetime.now()` に依存）のため
ユニットテスト対象外。旧実装 `src/RacePrediction/post_daily_race.py` の時点から同様の方針。

`make_time_id_list` / `update_weekly_time_id_list` / `make_html_prev_day` / `update_daily_html` は
旧 `src/RacePrediction/make_time_id_list.py`・`web/src/generators/make_race_card_html.py`
（いずれもPhase7cで削除）の同名関数の移植として2026-06-18に新規実装した
（README「### 完了済み」テーブル・[ProductionScheduleSequence.pu](../ProductionScheduleSequence.pu)参照）。

## post_daily_race_pred の処理フロー（参考）

```
1. race_card_dataset_manager.get_time_id_list(race_day)  # 当日の発走時刻リスト取得
2. html_manager.add_race_day(race_day)                   # カレンダーJS更新
3. daily_index_generator.make_daily_index_page(race_day) # 日次インデックスHTML生成
   └─ 過去7日分も再生成（リンク更新のため）

4. ループ（1分ごと、全レース終了まで）:
   ├─ 20分前になったら:
   │   ├─ race_card_builder.make_race_card(race_id)          # 出馬表＋予想スコア生成
   │   ├─ race_card_dataset_manager.save_race_cards(...)      # CSV保存
   │   ├─ prediction_publisher.make_race_text(...)            # 予想テキスト生成
   │   ├─ post_race_pred(race_id, race_day)                   # X/メール投稿
   │   ├─ race_page_generator.make_race_card_html(...)        # レースページHTML生成
   │   └─ 直前レースがあれば:
   │       ├─ netkeiba_scraper.scrape_day_race_result(...)    # 結果スクレイピング
   │       ├─ race_result_dataset_manager.save_race_result_for_race_id(...)
   │       ├─ netkeiba_scraper.scrape_race_returns_dataframe(...)  # 配当スクレイピング
   │       ├─ race_info_dataset_manager.save_race_return_for_race_id(...)
   │       └─ race_page_generator.make_race_card_html(...)    # 結果反映HTML再生成
   └─ sleep(60)

5. 最終レース終了後 30分待機（sleep(1800)）:
   └─ 全開催場の最終レースについて結果・配当を取得・保存・HTML再生成
```

## テスト内容の要約

テストでは `monkeypatch` を使い、外部依存（ファイルシステムのパス・`post_text_data` の実送信）を
差し替えて、**パスの組み立てロジックのみ**を検証する。

- **test_post_race_pred_posts_prediction_text**:
  `RACE_PREDICTION_TEXT_PATH` を `tmp_path` に差し替えた状態で
  `post_race_pred("202405010101", date(2024, 1, 27))` を呼ぶ。
  `prediction_publisher.post_text_data` に渡されるパスが
  `{tmp_path}/race_prediction/20240127/202405010101.txt` になることを確認する。

- **test_post_pred_return_posts_return_text**:
  `RACE_RETURN_REPORT_TEXT_PATH` を `tmp_path` に差し替えた状態で
  `post_pred_return(place_id=5, date(2024, 1, 27))` を呼ぶ。
  `prediction_publisher.post_text_data` に渡されるパスが
  `{tmp_path}/race_returns/20240127/05_tokyo_pred_score.txt` になることを確認する
  （`constants.PLACE_LIST[place_id - 1]` = `"05_tokyo"` でパス名が決まる）。

## 新規実装の関数（2026-06-18追加）

### make_time_id_list / update_weekly_time_id_list

- **test_extract_race_time_and_name_returns_expected**: `scrape_race_card`のinfoの
  例（`["3歳未勝利", "10", "05発走", ...]`）から、発走時刻`"1005"`・レース名
  `"3歳未勝利"`を正しく抽出することを確認（オフライン）。
- **test_make_time_id_list_returns_expected**（network）: `get_daily_id`を
  `[FIXED_RACE_ID]`にmonkeypatchした状態で`scrape_race_card`を実際に呼び、
  `[["1005", "202405010101", "3歳未勝利"]]`が返ることを確認。
- **test_update_weekly_time_id_list_saves_next_7_days**: `make_time_id_list`を
  monkeypatchし、`base_day`から7日後〜1日後の7日分について
  `save_time_id_list`が呼ばれることを確認。
- **test_update_weekly_time_id_list_skips_days_with_no_races**: 開催の無い日は
  保存処理が呼ばれないことを確認。

### make_html_prev_day

- **test_make_html_prev_day_generates_cards_and_html**: `get_time_id_list`が
  2レース分返す状態で、`add_race_day`→`make_daily_index_page`（当日+過去7日+末尾の
  再生成で計9回）→各race_idについて`make_race_card`/`save_race_cards`/
  `save_race_info_df`/`update_horse_name_id_map`→`make_daily_race_card_html`の
  呼び出し順を確認。
- **test_make_html_prev_day_noop_when_no_time_id_list**: `time_id_list`が空なら
  `add_race_day`以降が呼ばれない（即return）ことを確認。

### update_daily_html

- **test_update_daily_html_saves_results_and_returns**: `scrape_day_race_result`/
  `scrape_race_returns_dataframe`の結果が`save_race_result_for_race_id`/
  `save_race_return_for_race_id`に保存され、最後に`make_daily_race_card_html`が
  呼ばれることを確認。

## 関連する既存バグの修正

`make_time_id_list`の検証中、`src/logic/scraping/common.py`の`fetch_soup`が
全ページをEUC-JP固定でデコードしていたバグを発見した。`race.netkeiba.com`の
出馬表ページ（`scrape_race_card`が参照）は実際にはUTF-8で配信されており、
固定デコードだと列名が文字化けして`KeyError`になる
（`db.netkeiba.com`はEUC-JPのため、今まで気づかれていなかった）。
`response.apparent_encoding`による自動検出に修正し、`-m network`の全8テストで
回帰がないことを確認済み。
